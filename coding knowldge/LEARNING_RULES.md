# 做題守則

> 我卡的不是「想不出解法」，是「想法轉不成 code」。
> 我不是沒毅力，是卡住的那一刻沒有出口。

---

## 開始前（30 秒）

```
□ 現在在藥效窗口內嗎？
   在  → 做新題
   不在 → 只做低階任務（整理筆記、看解法、補 LOG）

□ 計時器設 8 分鐘

□ 在 LOG.md 先寫下題號（等級做完再補）
```

## 卡住時：先站起來

**第一個動作是離開椅子，不是想。**

站著 30 秒，坐回來，然後動筆做這四件事：

```
1. 寫下「我卡在：____」
   寫不出來 = 我還沒定義問題，這就是卡點

2. 把輸入畫出來
   陣列畫格子標 index／list 畫箭頭／樹畫節點
   手畫，不准在腦中畫

3. 手算，寫下每一步變數的值

4. 寫下「我需要一個東西幫我記住 ____」
```

這四步全是**動作**。我可以執行動作，不能執行「靜靜地想」。

做完還卡 → 領 L1。

---

## 想法轉不成 code 時

這是我的主要卡點。填完這四行，code 通常自己就出來了：

```
我要維護的東西是：______
它什麼時候改變：______
答案什麼時候出現：______
迴圈／遞迴什麼時候停：______
```

遞迴題多一行：**這個回傳值代表什麼？**（這裡錯了後面全錯）

---

## 樹題：只填這三格，先不要寫 code

```
1. base case：什麼時候不用再往下？
   ______（幾乎都是 root == null）

2. 回傳值代表什麼？（意義，不是型別）
   「以 root 為根的這棵子樹，______」

3. 假設左右子樹的答案已經在我手上了，我這一層怎麼組合？
   ______
```

第 3 格的關鍵字是**「假設已經在我手上」**。

遞迴要求的不是追蹤，是**信任** —— 追到第三層一定崩。
只處理當前這一層，下面的相信它已經做完了。

我卡住的時候，幾乎都是第 2 格沒填清楚（110 卡在「回傳高度還是布林」，226 卡在「回傳值只是一個 TreeNode」）。
第 3 格通常只有一行，難的從來不是它。

畫圖只畫三個節點就好。遞迴只需要看一層。

**寫完骨架後，花 1 分鐘找一個能打爆它的測資。**

問「什麼輸入會讓這個寫法錯？」
不要問「這樣對嗎」—— 那個問法我會自我說服。

骨架變成反射是好事，但反射的東西不會被檢查。
111 就是預設骨架失效的題（單邊子樹）。這種題只能靠主動找反例抓到。

常見的打爆測資：空樹、單節點、只有左子樹、只有右子樹、一條直線的樹。

### 要不要開 helper（08-07 補）

判斷法只有一條：

> **題目給的簽名，裝不裝得下遞迴要往下傳的資訊？**
> 裝不下 → 開 helper 加參數　／　裝得下 → 不要開

- 1022 `sumRootToLeaf(root)` 塞不進「累積值」→ 開 `hand(node, n)`
- 98 `isValidBST(root)` 塞不進「上下界」→ 要開
- 112 `hasPathSum(root, targetSum)` 本身就帶著剩餘的 sum → **不用開**

第 2 格填錯會偽裝成第 3 格卡住。112 就是：填成「還剩多少」(int)，型別根本表達不了「存不存在」(boolean)，
於是「兩邊都有時要回傳什麼」怎麼想都想不出來。**卡在第 3 格時，先回頭看第 2 格。**

## array / string：填四問，先不要寫 code

樹題靠遞迴用三格，array/string 靠迴圈用四問。完整說明和範例看 `12_四問（array-string 框架）.md`。

```
1. 我開了哪些變數／指標，每個代表什麼？（每一個都要帶「範圍」）
   例：max = nums[0..i-1] 的最大值　／　slow = 下一個該寫入的位置

2. 迴圈不變式：每一輪「開始的瞬間」，什麼事情一定是真的？   ← 最重要
   不是「迴圈做什麼」，是「跑到這裡為止已經保證了什麼」

3. 邊界：從哪開始？到哪停？< 還是 <=？

4. 迴圈結束時，答案在哪個變數裡？
```

**第 2 問就是樹題的第 2 格。** 兩邊都是「講清楚這東西的意義」，也都是我真正會卡的地方。

驗證法：不變式 + 迴圈結束條件，要能推出「這個變數就是答案」。推不出來就是寫錯了。

**填不出第 2 問時照做，不要坐著想：** 寫暴力版 → 拿 5 個元素在紙上畫每一輪的變數值 →
看著表格用一句帶範圍的中文描述那個變數 → 那就是不變式。

沒有不變式的下場（08-06 診斷測）：五題全部只剩「巢狀迴圈掃過所有組合」，全是 O(n²)。

## 第一版一定要是爛的

**我真正的卡點：不是想不出來，是不敢寫下來。**

想到了但不動筆，因為寫下去就可能是錯的。於是停在「想」，而想沒有終點。
停太久 → 不舒服 → 分心 / 問 AI。

破解方式：**把「寫錯」設成目標。**

> 第一版：先寫一個我明知道是錯的版本。

目標是「錯」，就不可能失敗，動筆成本歸零。
而刻意寫的爛版本，通常有七成是對的。

配套：

- 開 `scratch.java` 草稿檔，在裡面想。正式檔案有「這是成品」的心理重量
- 手寫優先。紙容易塗改，鍵盤有要寫對的壓力
- **空白不能被 debug，錯的可以。** 一版有 bug 的 code 價值遠高於一片空白

## 問 AI：一次只領一級

| 級 | AI 只能給我 | 代價 |
|---|---|---|
| L0 | 什麼都沒給 | — |
| L1 | 只講類別名，不解釋 | — |
| L2 | 一句話講關鍵觀察 | 自己再寫 15 分鐘才能升級 |
| L3 | pseudocode 骨架，不含 Java | 同上 |
| L4 | 完整解法 | **本題算未學會，7 天後重做** |

**永久禁止：**「接下來呢」「給我提示」「這題怎麼做」

**隨時可問（不算提示）：**

- Java 語法
- 「這行的 i 是多少」← 讓 AI 當 debugger
- 「我的想法是 XXX，只回答 對／錯，不要解釋」

**AI 越級時，回一個字：「越級」。** 它要退回上一級重來。
（08-07 加：AI 在 257 直接把兩個 helper 簽名端出來，那是我要自己想的東西。）

## 結束：一行

格式：`題號 | 等級 | 卡點一句話 | 重做日期`

```
226 | L1 | 卡點：不知道遞迴回傳什麼 | 重做:08-01
```

日期一律寫 `MM-DD`。紀錄全部進 `LOG.md`，這份檔案只放規則。

要盯的只有 **L3/L4 的比例往下掉**。題數不代表任何事。

**重做規則：**

```
L0      → 不用排
L1 以上 → 7 天後重做
```

「重做」= 開新檔案，不看舊 code、不看筆記，從零重寫。

每天開工前掃一眼 LOG，看有沒有今天到期的。五秒的事。

**重做優先於新題。** 塞不下的時候砍新題，不要讓重做堆積 —— 堆起來我就不會做了。

## 兩條不可協商

1. **凌晨不碰題目。** 沒有藥效、抑制最弱、衝動最強、學習效率最差，四件事一起發生。那不是努力，是在最不可能成功的時段挑最難的任務。

2. **一次只改一件事。** 想優化流程、換工具、重建資料夾結構的衝動 = 高級拖延。記下來，做完今天這題再說。
